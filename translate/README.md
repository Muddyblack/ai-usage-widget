# Translations

One gettext catalog per language, `translate/<lang>.po`, translates
everything a user reads, on every platform:

- the UI (`ui/`, `hosts/`): `shell.i18n("…")` / `i18nc` / `i18np` calls;
- the text the backend words itself — row labels, details, tooltips, errors —
  written as `tr("…")` in `backend/aiusage` (see `backend/aiusage/messages.py`).
  The envelope carries each such field's template beside it (`labelI18n`,
  `detailI18n`, …) and the UI translates it with the same catalog.

`translate/Messages.sh` extracts both into `template.pot` and merges it into
every `.po`; every host reads the `.po` at runtime (`ui/js/I18n.js`), and the
KDE package also gets a compiled `.mo` for its store name and description.

## Translating on Weblate

The easiest way to help: open the project on Weblate, pick a language and
translate in the browser. Weblate commits back to this repository through a
pull request, and the next release ships it. A language does not have to be
finished to be useful — untranslated strings simply show in English.

## Translating locally

```bash
make new-language CODE=de      # starts translate/de.po from the template
# edit translate/de.po (Poedit, Lokalize, or any text editor)
make translations              # re-extract and merge, keeps your work
make check-translations        # every catalog must compile
```

Placeholders are `%1`, `%2`, … and may be reordered (`"Aujourd'hui (%2 %1)"`).
Lines starting with `#.` in the catalog are notes for translators; add one in
the source with a `// TRANSLATORS: …` comment (`# TRANSLATORS: …` in Python)
on the line before the string.

`translate/complete-languages` lists the languages CI requires to stay 100%
translated; any other language may be partial.

## Setting up Weblate (maintainers, once)

Weblate is free for open-source projects at <https://hosted.weblate.org>
("Libre" plan). Repository side, nothing else is needed — the layout below is
what Weblate expects.

1. Sign in with GitHub, create a project (name: *AI Usage Monitor*, website:
   the GitHub repository) and apply for Libre hosting.
2. Add one component:
   - **Source code repository:** `https://github.com/Muddyblack/ai-usage-widget`,
     branch `master`; **Repository push URL:** the same, via the Weblate
     GitHub integration (it then opens pull requests instead of pushing).
   - **File format:** *gettext PO file*
   - **File mask:** `translate/*.po`
   - **Monolingual base language file:** *(empty)* — PO is bilingual.
   - **Template for new translations:** `translate/template.pot`
   - **Language filter:** `^[a-z]{2,3}(_[A-Z]{2})?$`
   - **Adding new translation:** *Create new language file*.
3. Add-ons: enable **"Update PO files to match POT (msgmerge)"** so a new
   string reaches every language. Leave **"Update POT file"** off: the
   template is produced by `translate/Messages.sh`, which knows the QML and the
   Python sources; CI keeps it and the `.po` files in sync.
4. Under *Settings → Commit messages*, a short prefix like `i18n:` keeps the
   history readable.
5. Link the project in the README ("Help translate") once it is public.

`template.pot` is committed for Weblate and regenerated by
`make translations`; commit it together with the `.po` files.
